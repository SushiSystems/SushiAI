# Compile time and include hygiene: plan

**Status:** Open — written 2026-10-26. The owner asked that day for the places where SYCL is included or compiled for nothing, and for the compile time they cost to come down without breaking SOLID. Builds stay forbidden until the Ultralytics models run, so every task here is written and syntax-checked; the owner's build measures it.

## 1. The goal

A clean build of SushiAI compiles each translation unit once, in the mode it needs: device
compilation only for the units that instantiate a kernel, a public header includes only what its
declarations use, and no source is compiled once per executable. Behaviour does not change; every
test passes before and after.

## 2. What was measured, 2026-10-26

Read from the tree and from `build/build.ninja`; nothing was compiled.

| Finding | Where | Cost |
| --- | --- | --- |
| `-fsycl` is a PUBLIC compile option of every module object library, every internal module and every tier library, so every test and program inherits it | `cmake/SushiAISyclTarget.cmake`, applied in `cmake/SushiAIModule.cmake` (three calls) | Each of about 880 units (373 module, 480 test, 30 application) runs a device pass, a host pass and the integration header step |
| Five units instantiate a device kernel: they include `SushiBLAS/elementwise/dispatch.hpp` and hand it a functor | `graph/source/lowering/elementwise.cpp`, `fused.cpp`, `optim/source/adamw.cpp`, `gradient_clip.cpp`, `sgd.cpp` | The other units compile device code that is empty |
| `replica_kernel.cpp` and `replica_accumulator.cpp` name `sycl::queue`, `sycl::event` and `sycl::half` on the host only | `core/distribution/source/` | Need the SYCL headers, not the device pass |
| `<sycl/sycl.hpp>` reaches SushiAI through SushiBLAS: `tensor/tensor.hpp` includes it for one accessor, `sycl::device device()`; `engine/task_recorder.hpp` and `elementwise/dispatch.hpp` include it too | SushiBLAS public headers | 121 SushiAI files include `tensor.hpp`, 92 include `engine.hpp`, which includes `tensor.hpp` |
| 52 SushiAI public headers include `SushiBLAS/engine/engine.hpp` | `modules/**/include` | Every includer of those headers parses SYCL |
| `graph/fusion_selector.hpp` includes `SushiBLAS/launch/device_policy.hpp`, which pulls `sycl/ext/oneapi/matrix/matrix.hpp`, to hold a `Device::Profile` by value | `modules/core/graph` | Reaches `training_step.hpp`, `trainer.hpp`, `lowering.hpp`, the umbrella and their includers |
| The twelve program sources in `SUSHIAI_PROGRAM_SHARED` are listed in each of the four program executables, and again in the program tests | `applications/programs/CMakeLists.txt`, `tests/applications/programs/CMakeLists.txt` | `domains_vision.cpp` and the rest compile five times |
| Every one of about 60 executables links with `-fsycl` | inherited link option | A device link step per executable; needed only where device objects are linked |

The DPC++ header `sycl/sycl.hpp` compiles without `-fsycl`: it warns, and
`SYCL_DISABLE_FSYCL_SYCLHPP_WARNING` silences it. Host units can therefore drop the device pass
before SushiBLAS stops exporting SYCL.

## 3. Rulings

| Subject | Ruling |
| --- | --- |
| Scope | SushiAI's own build files, headers and sources. SushiBLAS and SushiRuntime headers are another repository's public surface: changes there are proposals for the owner (section 6) |
| Device sources | A module names the units that instantiate kernels; only those compile with `-fsycl`. The rule lives in one CMake function, and a checker refuses a unit outside that list that includes a kernel-launching header |
| Headers | A public header includes what its declarations use. A type it names only by reference or pointer is forward-declared, when its owner ships a forward header or the type is SushiAI's own |
| Builds | None until the Ultralytics models run. Each task is syntax-checked file by file; the owner's build gives the before and after times |
| Mode | Parallel, at most three workers, as in the Ultralytics plan |

## 4. Tasks

Hierarchy first: build functions, then the modules that call them, then headers, then sources.

| Id | Task | Waits on | Accepted when |

| C3 | `tools/build/check_device_sources.py`: a unit that includes a kernel-launching header (`elementwise/dispatch.hpp`, `functor_map/`, `launch/`, `reduction/`, `random/dispatch.hpp`, the runtime's `emit_*`) directly or through a SushiAI header must be in its module's `DEVICE_SOURCES` | C2 | the checker passes on the tree and fails on a fixture that moves one device unit out |
| C4 | `fusion_selector.hpp` stops including `launch/device_policy.hpp`: the selector holds the profile fields it reads as a SushiAI type, and `for_engine` reads the profile in the source | nothing | no SushiAI header includes a `SushiBLAS/launch/` header; `test_fusion_selector.cpp` unchanged in what it pins |
| C5 | The 17 headers that include `engine.hpp` for `SushiRuntime::span` alone include `SushiRuntime/core/span.hpp`, and the two that include it for nothing drop it (`REPORT.md` section 3) | inventory | each changed header and one includer of it syntax-check |

The owner's build follows C8: a clean build timed before and after, the number of units compiled
with `-fsycl`, and the whole test suite.

## 5. Not verified

- That DPC++ refuses, at compile or link time, a kernel instantiated in a unit compiled without
  `-fsycl`. If it only fails at run time, C3's checker is the guard and the full test run is the
  proof.
- That linking host-only objects and device objects into one static library and one executable
  with `-fsycl` on the link line behaves as today. DPC++ documents it; this toolchain has not shown
  it.
- The size of the gain. The device pass is roughly the cost of the host pass for a unit with no
  kernel, but the share of `sycl.hpp` parsing in each pass is not measured.

## 6. Proposals for the owner, outside SushiAI

| Proposal | Repository | Effect |
| --- | --- | --- |
| `tensor.hpp` drops `<sycl/sycl.hpp>`: `device()` moves to a header of its own or returns a SushiRuntime device handle | SushiBLAS | 121 SushiAI files stop parsing SYCL through `tensor.hpp` |
| A forward header, `SushiBLAS/fwd.hpp`, declaring `Engine` and `Tensor` | SushiBLAS | SushiAI headers that pass them by reference include it instead of `engine.hpp` |
| `task_recorder.hpp` keeps SYCL out of its public part | SushiBLAS | 30 SushiAI includers |

With proposal 2 in, C6 replaces `engine.hpp` in 27 SushiAI headers; the five with most includers are `materialised_dataset.hpp` (29 sources), `objective.hpp` (23), `init.hpp` (17), `host_values.hpp` (10) and `training_step.hpp` (8).

These are cross-repository public surfaces; they wait for the owner's word.
